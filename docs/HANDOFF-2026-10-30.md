### Two reconciliations (these decisions win over both the spec wording and the continuation prompt)

1. **CSS layer order.** Spec section 12 lists `@layer reset, base, components, responsive, studio, photography, refinement, atelier, motion;` with an unlayered `tokens.css`; the continuation prompt uses `@layer reset, legacy, tokens, atelier, pages, motion;` with the legacy files wrapped as sub-layers of `legacy` (`base, components, responsive, studio, photography, header, refinement`, preserving today's cascade). **Use the continuation prompt's structure.** It satisfies every invariant spec section 12 cares about (all legacy CSS below `atelier`; token custom properties beat legacy `:root` blocks; no unlayered rule can beat `atelier`) and adds a `pages` layer so route CSS (`home.css`, `portfolio.css`, `services.css`, `pages.css`) wins over `atelier` without specificity games. Until a route file is rewritten inside `@layer pages`, its current unlayered rules still beat `atelier` — rewrite each route's CSS as that route is rebuilt.

- Tiers per spec 9.2 (`off | ceramic | glass`): glass = `materials.glass` + brass; ceramic = matte ceramic sage/cream + brass; never transmission on ceramic. Share one material instance per kind; dispose on unmount.
- Spin axis default `z` (in-plane, always reads as the logo) with a mild resting three-quarter tilt (≈ x −0.2, y 0.26). Hero 1 turn/48s; others 1 turn/60s. Entrance scale .96→1 / rotation.y −.2→0 over `--dur-xl` expo when motion is allowed; pointer lean ≤ ±0.14 rad X / ±0.18 rad Y via `MathUtils.damp` λ=4 (fine pointers only; pointer from `useSceneMotion`); `scrollProgress` 0..1 → spread `p×0.6`, rotation.z `+p×0.35`, position.y `+p×0.6`; `onReady` once after the first rendered frame (flag in useFrame + deferred callback). - Lighting per spec 9.3 — but three's physical light units make `spotLight intensity 2` / `pointLight 0.6` far too weak at ~7 units: expect to tune the spot to ~60–120 cd (or `decay 0`) and the point to ~15–40 by looking at screenshots. - Backdrop (judge must-fix: transmission over a transparent canvas looks muddy). three facts: `transparent: true` materials are NOT drawn into the transmission pass, and an opaque plane would paint a visible square over the page gradient. Use a "refraction-only" plane: PlaneGeometry(12,12) at z −6, opaque ShaderMaterial (`toneMapped: false`, `depthWrite: false`) painting the radial pool `#1A3B2E → #11291F` (smoothstep(.05,.62,d) from uv (.58,.56); linear colours + `#include <colorspace_fragment>`), and in `mesh.onBeforeRender(renderer)` set `material.colorWrite = renderer.getRenderTarget() !== null` so it is only visible to the transmission pass. Put it on camera layer 1 so drei `ContactShadows` never sees it. Mount only in the glass tier. If glass still reads dark, brighten the centre (e.g. `#24503F`).
- Shadows: wrap drei `ContactShadows` (opacity .4, blur 2.6, scale 8, far 3, colour #061611, resolution 512 glass / 256 ceramic) with `frames={1}` when static and `Infinity` only while pieces move; if flipping `frames` does not re-bake, remount with a `key`. ## 9. Gotchas collected so far

- Import `lazyScene` from `@/components/three/lazy` in page-level client code, not from the barrel, or three/drei end up in the page chunk. `lazyScene(() => import("./x-scene"), <Fallback/>)` must sit at module scope of a `"use client"` file.
- Size the SceneCanvas parent explicitly (aspect-ratio / min-height); the canvas is 100%/100%. Give the fallback the exact footprint to avoid layout shift.
- Brass needs an environment (metalness 1 is black without one). Glass (`transmission`) on an alpha canvas samples the transparent clear colour → pale/washed; use the refraction-only backdrop (above).
- `useSceneMotion().pointer` is a ref — read in `useFrame`, never copy to state. No `setState` in `useFrame`.
- Under reduced motion `SceneCanvas` uses frameloop `demand`: nothing in `useFrame` runs; apply static poses in effects and call `invalidate()`.
- drei `Float` triggers the THREE.Clock deprecation warning path; a tiny own float in `useFrame` is quieter.
- `MotionConfig reducedMotion="user"` must wrap motion-based wrappers; `motion/react` is imported only inside client components.
- Legacy CSS (`globals.css` base/components/responsive, `studio.css`, `refinement.css`, `header.css`, `photography.css`) is layered below `atelier`, not deleted; cleanup is Phase 2 step 6.
